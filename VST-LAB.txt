====================

Usage
-----
Open an audio project and select a track in the editor. The inspector has one
Audio plugins button opening the draggable, modeless manager. Choose a plugin
folder on the left to identify its effects, select an effect and add it to the
named track/master destination on the right. Sources initially contain no folder;
only explicitly selected sources are remembered. Empty lists never scan system
defaults. On macOS, system Audio Units are a separate explicit source choice.
The initial position leaves transport visible, and resizing recenters the panel.
Closing it retains the selected target and catalog; native windows stay open.
The library groups results by vendor, declared effect type or plugin format.
Scanning runs on the blocking worker with one isolated helper per package. The
manager shows the active package, elapsed time and completion count, with Skip
and blacklist and Stop controls available while the scan is busy. A package that
exceeds ten seconds is terminated, excluded and followed by the next package.
Exclusions persist in plugin-blacklist.json and survive ordinary/forced rescans.
Remove an entry in the manager to invalidate its failure cache and retry during
the next scan. VST2 shell children/VST3 classes share their package exclusion;
the explicit system AU source is a whole metadata enumeration, not a per-unit test.
VST3 uses SDK metadata; VST2 categories stay coarse; unknown categories are not
guessed from names. AU currently uses vendor/format and actual component identity.
Track and master chains support adding, ordering, bypassing, removing and opening
the plugin's native window. Native edits are observed and automatically captured
into immutable content-addressed files; manual save and window close await the
latest state. Failed captures remain visible and can be retried. Export renders the same native graph before
the existing output encoding and publishing stage.
Export sessions select offline processing during control-thread preparation.
Plugins may choose different offline quality, latency or tail behavior. The host
notifies VST3/VST2 effects and AUs supporting the optional OfflineRender property;
it does not force a plugin to change its quality. Ordinary AUs without that
property keep their current effect path. Dedicated auol/batch-offline workflows
are outside the current adapter.
VST3 latency/tail queries and latency-change reactivation run on the control
thread while DSP is suspended. The worker reads an atomic timing cache; render
startup recovery is bounded per insert, including serial effect chains.

First-round boundaries
----------------------
Use mono/stereo local audio. Built-in track effects can precede the plugin chain
in the native graph. Recording saves dry microphone takes, with native plugins
processing accompaniment and recorded clips. Live input plugin monitoring,
hardware latency compensation, instruments/MIDI, sidechains, float64-only plugins and architecture bridging
are not supported. Maximum plugin tail is 30 seconds; exports report truncation.
Stable processing-latency changes are renegotiated with the same plugin instance,
preserving playback position, loop state and editor windows. Repeatedly unstable
latency stops playback after a bounded recovery attempt.
IMessage/IAttributeList hosting, hidden/bypass parameter delivery and preset value
refresh are implemented; additional plugins still need compatibility checks.
Plugin crashes interrupt the audio process. The plugin panel can explicitly
reload the most recently saved state; uncaptured edits may be lost.

Third iteration (2026-10-23 UTC)
------------------------------
A bypassed VST3 whose binary, class, saved state, or initialization is unavailable
can be left in its original slot while the rest of the project plays/exports.
The host reports skipped slot identities and reasons; it never substitutes a
new default state or replaces the project's original opaque state reference.
An enabled unavailable plugin still blocks processing. Changing bypass state
rebuilds the graph, so re-enabling a previously skipped slot cannot silently
leave dry audio in its place. Previously open windows are restored only for
instances that actually loaded.

The inspector can relocate an existing slot to a scanned installation of the
same plugin class. Its slot identity, state and other metadata are preserved;
a different class cannot inherit that blob. Recovery edits capture the surviving
native graph without first trying to apply a project that has already failed,
retaining current GUI edits of healthy plugins.

The plugin library now presents scan failures and explicit retry. The new
plugin_host_scan_report command returns plugins, failures, scanned and cached;
the original array command remains available. Successful and failed probes are
fingerprint-cached, and a forced scan retries them. Missing custom paths report
an error; absent platform-default paths are quietly skipped. Only the child
process's project copy loses an unreadable bypassed state; persisted data keeps
its original reference for later recovery.

Fifth iteration: VST2 and AUv2 effect integration (2026-10-24 local time)
--------------------------------------------------------------------
The native graph now uses a shared effect adapter for VST3, VST2 and AUv2;
track/master inserts can mix formats with the same existing PDC, crash recovery,
snapshot barriers and offline render path. Capabilities advertise VST2 on all
three desktop platforms, and AUv2 only on macOS. Unsupported enabled formats
still fail; bypassed foreign/missing slots retain their original opaque state.

VST2 supports native-architecture VST 2.4 float32 mono/stereo effects. It discovers
Windows DLLs, macOS .vst bundles and Linux .so files. Shell containers, instruments,
MIDI, additional buses, old Carbon views and architecture bridging are excluded.
Windows/macOS can open native windows; macOS sends Cockos' Cocoa negotiation
before passing an NSView. Linux VST2 uses generic parameter controls. Host callbacks
use per-instance atomics and per-thread process levels; audio processing does not
acquire a host mutex. Shutdown retires off-thread instances to their creating UI
thread before closing windows and unloading their libraries.

VST2 state uses a versioned envelope bound to effect ID, binary version and
parameter count. Chunk state and parameter-only state are supported, with exact
length/representation validation and a 32 MiB limit. A different binary version
is deliberately rejected rather than implicitly migrating its saved state.

AUv2 enumerates registered synchronous components in a separate scan helper;
the system catalog is reprobed each scan. AU slots store their component identity
as both pluginId and path, independent of the installed component bundle location.
Only global writable parameters and a single main input/output bus are hosted.
Native Cocoa views, AUv3/asynchronous components, instruments and additional buses
are excluded. ClassInfo is stored as a bounded binary property-list dictionary;
restored state is preserved across initialization without resending old defaults.
Latency/tail notifications only publish an atomic dirty flag. Property queries
run during stopped-worker renegotiation, and latency accumulation saturates so
invalid reported values cannot wrap into a seemingly valid delay. Tail limits
remain visible to exports. Input callbacks support repeated/overlapping buffers
without constructing conflicting Rust slice references.

The inspector now offers generic parameter controls with search, pagination,
finite/range validation, toggles and choices. Requests use the session queue;
project, session and slot identities prevent stale replies from applying to a
replacement instance. Native plain-value caches are updated only after enqueue
success. Scanning, state references and same-class relocation handle all formats;
AU registry entries do not offer file relocation. Existing projects without
plugins continue using their original playback/export route.

Sixth iteration: native editors and complete platform checks (2026-10-24 local time)
-------------------------------------------------------------------------------
The original format/platform goal is tracked as follows (implementation, not a
claim of native runtime compatibility):
  Windows: VST2/VST3 effect DSP, state, generic controls and native editor windows.
  macOS:   VST2/VST3/AUv2 effect DSP, state, generic controls and native Cocoa views.
  Linux:   VST2/VST3 effect DSP, state, generic controls and X11/XWayland windows.
  AAX:     recognized and reported unsupported; no host loader is implemented.

Linux VST2 uses the modern JUCE/DPF contract: the numeric parent XID is passed in
effEditOpen's pointer argument, with value zero. The shared host completes the
parent window creation with XSync before a plugin on a different Display can
attach. Resize requests are coalesced; plugins may provide their first rectangle
after attachment, and old rectangles cannot overwrite newer SizeWindow requests.
Native Wayland and older shared-Display/_XEventProc extensions remain outside scope.

AU native editors resolve the component's AUCocoaUIBase factory and retain its
bundle, factory and NSView until the view has detached. AUEventListener callbacks
coalesce plain parameter values into bounded atomic mailboxes on the UI run loop.
Generic-to-native-to-original-value changes remain observable. Closing or rapidly
reopening a view captures pending final values before unregistering its listener.
Units with no compatible Cocoa view can still use the generic parameter panel.

AU view creation/closure runs behind the processing snapshot barrier. A user-closed
window is detached behind the same barrier and its final edits reach the current
session in the same idle tick. Session teardown joins the audio worker before
closing native views, then destroys the processors. Off-thread retirement is drained
by the UI loop. If AUListenerDispose fails, disabled callback storage and its unit
remain alive until helper exit, preventing a callback into a disposed component;
the affected view cannot be reopened until the helper is reloaded.

Eighth iteration: AUv3 and VST2 shell integration (2026-10-24 UTC)
----------------------------------------------------------------
VST2 scanning enumerates up to 4096 unique shell children without instantiating
each child. Descriptors retain the binary path, child vst2:8HEX identity and
isShellChild. Their isInstrument is null until actual loading validates effect
category and bus layout. The selected ID is instance/thread scoped before the
plugin entry point, through state/parameter/editor calls, processing and close.
The state envelope remains bound to the actual child's ID, version and parameters.

AU discovery now includes AUv3 and components requiring asynchronous creation.
Legacy au: identities remain unchanged; extensions use au3: so v2/v3 components
sharing four-char codes cannot reuse one another's state. AudioComponentInstantiate
and kAudioUnitProperty_RequestViewController use Apple's documented compatibility
bridge. Each asynchronous operation waits at most ten seconds while pumping the
main event loop. Late controllers release on the UI thread before retiring units.
Load/update/export preparation allows 20..120 seconds according to AU slot count,
including bypassed slots that still initialize for state/controller access.
Components missing the supported C parameter/state/DSP bridge report failures.
Native 64-bit parameter addresses are not cast into 32-bit parameter IDs.

The library labels AUv2/AUv3, VST2 Shell and VST3 variants explicitly. Scans expose
auVersion/isShellChild and nullable instrument classification; cache version 2
invalidates older unsupported-shell results. Single AU IDs can be inspected with
--plugin-scan au:... or --plugin-scan au3:... on macOS.

The portable manual harness uses the descriptor's actual format and supports:
  python tests/manual/vst_real_plugin_smoke.py --host HOST --plugin BINARY_OR_AU_ID \
    --plugin-id EXACT_ID --ffmpeg FFMPEG --output-dir ARTIFACTS
Append --editor for native windows and --param-id ID (optionally --param-value N)
for parameter/audio checks. Without these options those checks are reported as
